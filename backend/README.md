# লাইভ বাস লোকেশন API (সস্তা কাঠামো)

Cloudflare Worker + D1 ডেটাবেস। সুপারভাইজারের অ্যাপ লোকেশন পাঠায়, কাউন্টার ১৫ সেকেন্ডে একবার জিজ্ঞেস করে (পোলিং)। কোনো পেইড ম্যাপ বা রাউটিং API লাগে না।

## কেন এই কাঠামো

| বিষয় | যেভাবে করা | খরচে প্রভাব |
|---|---|---|
| সর্বশেষ অবস্থান | প্রতিটি ট্রিপের জন্য `live_positions`-এ একটাই সারি, প্রতি পিং-এ আপডেট | পিং প্রতি ১টি লেখা |
| চলার পথের ইতিহাস | ট্রিপপ্রতি মিনিটে সর্বোচ্চ ১টি সারি (`position_history`) | লেখা ৫ ভাগের ১ ভাগ |
| কাউন্টারের পোলিং | Workers ক্যাশে ৫ সেকেন্ড রাখা; একই কোম্পানির সব কাউন্টার একটাই ডেটাবেস রিড ভাগ করে | রিড খুব কম |
| অপরিবর্তিত ডেটা | `ETag` মিললে খালি `304` উত্তর | ডেটা ট্রান্সফার কম |
| পুরনো ডেটা | প্রতিদিন রাতে ৪৫ দিনের পুরনো ইতিহাস আর ২৪ ঘণ্টার পুরনো লাইভ সারি মুছে ফেলা | স্টোরেজ সীমার মধ্যে |
| কোম্পানির আলাদা ডেটা | প্রতিটি কোয়েরিতে `company_id` আসে টোকেন থেকে, কখনো URL থেকে নয় | এক কোম্পানি আরেকটার বাস দেখতে পারে না |

Durable Objects আর WebSocket ইচ্ছা করে ব্যবহার করা হয়নি। অনেক বাস সারাদিন সংযুক্ত থাকলে ওগুলোর "চালু থাকার সময়" চার্জ বেশি হয়। আরও দ্রুত রিয়েল-টাইম লাগলে পরে যোগ করা যাবে।

## API

| মেথড ও পাথ | কে ব্যবহার করে | কাজ |
|---|---|---|
| `POST /api/loc` | সুপারভাইজার | `{ trip_id, points: [{lat, lng, speed, heading, accuracy, t}] }` — এক বা একাধিক পয়েন্ট (অফলাইনে জমা থাকলে একসাথে) |
| `POST /api/loc/share` | সুপারভাইজার | `{ trip_id, shared: true/false }` — লোকেশন শেয়ারিং চালু/বন্ধ |
| `GET /api/live` | কাউন্টার, এডমিন | নিজের কোম্পানির গত ৬ ঘণ্টায় সক্রিয় সব বাসের সর্বশেষ অবস্থান |
| `GET /api/track/:trip_id` | যাত্রী (লগইন ছাড়া) | একটি ট্রিপের অবস্থান, ১০ সেকেন্ড ক্যাশ |

সব অনুরোধে `Authorization: Bearer <টোকেন>` লাগে (শুধু `/api/track` বাদে)। ডেটাবেসে টোকেনের SHA-256 হ্যাশ রাখা হয়, আসল টোকেন নয়।

যাচাই: বাংলাদেশের সীমার বাইরের, ১০০ মিটারের বেশি ভুলের, ভবিষ্যতের বা ২৪ ঘণ্টার পুরনো পয়েন্ট বাদ যায়। পুরনো পয়েন্ট দেরিতে এলে নতুন অবস্থানকে মুছে দেয় না।

## ক্লায়েন্ট কোড (`../client`)

- `location-sender.js` — সুপারভাইজারের অ্যাপ: বাস চললে ১২ সেকেন্ডে, থেমে থাকলে ৬০ সেকেন্ডে একটা পয়েন্ট; নেটওয়ার্ক না থাকলে জমিয়ে রাখে (প্রায় ৬–৭ ঘণ্টা), ফিরলে ক্রমানুসারে পাঠায়।
- `live-poller.js` — কাউন্টারের স্ক্রিন: ১৫ সেকেন্ডে পোলিং, ETag পাঠায়, স্ক্রিন লুকানো থাকলে থামে, নেটওয়ার্ক সমস্যায় ধীরে ধীরে অপেক্ষা বাড়ায় (সর্বোচ্চ ২ মিনিট)।
- `eta.js` — পৌঁছানোর সময়: বাসের অবস্থানকে রুটের স্টপেজ-লাইনে বসিয়ে বাকি কিলোমিটার বের করে, আর মসৃণ গড় গতি দিয়ে মিনিট হিসাব করে। থেমে থাকা (ফেরিঘাট, জ্যাম) গড় গতিকে নষ্ট করে না।

## চালু করার ধাপ

```bash
cd backend
npm install
npx wrangler login
npx wrangler d1 create bus-live          # প্রাপ্ত database_id wrangler.toml-এ বসান
npm run db:migrate                        # টেবিল তৈরি
npx wrangler deploy
```

কোম্পানি, ট্রিপ আর লগইন টোকেন যোগ:

```bash
npx wrangler d1 execute bus-live --remote --command "INSERT INTO companies VALUES ('sayra','সায়রা পরিবহন','active')"
node scripts/new-device.mjs sayra supervisor "রাশেদুল ইসলাম"   # টোকেন আর SQL দেখাবে
npx wrangler d1 execute bus-live --remote --command "<দেখানো SQL>"
```

ট্রিপ (`trips` টেবিল) টিকিটিং অংশ থেকে প্রতিদিনের সময়সূচি অনুযায়ী তৈরি হবে।

## পরীক্ষা

```bash
npm test                                   # সাহায্যকারী ফাংশনের টেস্ট
node --test ../client/test/*.test.mjs      # ক্লায়েন্ট কোডের টেস্ট
npm run db:migrate:local && npx wrangler dev --local
node scripts/smoke.mjs http://127.0.0.1:8787 <সুপারভাইজার টোকেন> <কাউন্টার টোকেন> <অন্য কোম্পানির কাউন্টার টোকেন> <ট্রিপ> <অন্য কোম্পানির ট্রিপ>
```

`smoke.mjs` ১২টি বিষয় পরীক্ষা করে, যার মধ্যে আছে: অন্য কোম্পানির ট্রিপে লেখা যায় না, অন্য কোম্পানির কাউন্টার বাস দেখতে পায় না, অপরিবর্তিত ডেটায় 304, পুরনো পয়েন্ট নতুন অবস্থান মুছে দেয় না।

## আনুমানিক খরচ (Cloudflare-এর নভেম্বর ২০২৬-এর দামে)

ধরে নেওয়া: প্রতিটি বাস দিনে ১২ ঘণ্টা চলে, কাউন্টার ১৫ সেকেন্ডে একবার পোল করে।

| আকার | মাসিক খরচ |
|---|---|
| ~২০ বাস | $৫ (Workers Paid প্ল্যানের ন্যূনতম) |
| ~২০০ বাস | $১০–১৫ |
| ~১,০০০ বাস | $১০০–১৫০ |

ড্যাশবোর্ডে খরচের সতর্কবার্তা চালু রাখুন, আর বড় হওয়ার আগে আসল ব্যবহার দেখে আবার হিসাব করুন।
